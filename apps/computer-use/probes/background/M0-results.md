# M0 后台输入结果

## 结论边界

事实：在本次已激活过、随后被守卫完全遮挡的夹具中，公开 `CGEvent.postToPid`
能给 AppKit 和 Electron 输入单键码及逐字符中英文 Unicode。AppKit 也接受整串 Unicode；
Electron 的整串输入没有形成文本。公开组未完成两种夹具的坐标点击和滚动。
公开 AXPress 完成 AppKit 按钮操作；Electron 返回成功码但计数未变。

私有窗口路由字段与局部坐标补上 AppKit 坐标点击，以及两种夹具的滚动。
追加合成焦点、鼠标 tag、SkyLight 投递没有补上 Electron 点击；私有分组的单键码还出现不稳定。
这不证明所有私有路线均无效，更不证明 Chromium 一概不支持后台输入。

推荐 P2：公开逐字符 Unicode 与可验证的 AX 语义动作作为基础；如果决定采用私有增强，
先仅批准独立、可禁用的窗口路由实验实现，按动作报告能力。当前不建议把完整合成焦点路线
作为默认产品依赖，不承诺任意 Electron 坐标点击。正式发布前仍需 SIP-on 验证。
本报告只交付探针结果，不构成产品接线或下一阶段实施批准。

## 环境与前置条件

- macOS 26.5.1（25F80）、arm64；**SIP disabled**。
- Electron 44.7.0 / Chromium 152.0.7977.130；固定本地 HTML，禁用后台/遮挡节流。
- AppKit 使用 NSTextView、NSButton、NSScrollView；Electron 使用 textarea、button、可滚动 div。
- 独立 Developer ID 签名驱动，通过 LaunchServices 启动，父进程为 1、责任进程为自身。
  有效组开始及每条动作均重新检查辅助功能与事件投递权限，三项预检均为 true。
- 每个动作先 reset、给文本控件内部焦点，然后激活目标再激活守卫（warm）。
  输入阶段不调用目标激活；三扇窗口外框一致，目标被守卫完全覆盖。
- 操作后给仍在前台的守卫发全局 `v`，验证其收到而目标未混入；采样前台 PID 与真实光标。
- 中文为 Unicode 文本事件，不是中文输入法组合输入。未验证冷启动不激活、菜单、Canvas、
  多窗口、最小化、其他 Space、真人并发操作、拖动、快捷键或真实业务应用。
- **SIP-on 全部未验**。所有可能受 SIP 影响的结论需在开启 SIP 的机器上复核。

## 动作矩阵（SIP-off、warm）

“通过”同时要求实际控件变化正确、前台采样稳定、守卫键路由正常、真实光标采样无位移。
“失败”表示本候选投递后未得到预期控件结果，不代表已证明操作系统不允许该动作。

| 动作 | AppKit 公开 | AppKit 私有窗口字段 | Electron 公开 | Electron 私有窗口字段 |
|---|---|---|---|---|
| 单键码 `a` | 通过（3/3） | 不稳定（1/3） | 通过（3/3） | 不稳定（1/3） |
| 整串英文 `abcXYZ` | 通过 | 通过 | 失败（空） | 失败（空） |
| 整串中文 `中文测试` | 通过 | 通过 | 失败（空） | 失败（空） |
| 逐字符英文 | 通过 | 通过 | 通过 | 通过 |
| 逐字符中文 | 通过 | 通过 | 通过 | 通过 |
| 坐标点击按钮 | 失败 | 通过（计数 +1） | 失败 | 失败 |
| 滚动 | 失败 | 通过（120px） | 失败 | 通过（120px） |
| AXPress 语义点击 | 通过（计数 +1） | 不需要私有路径 | 返回 0、计数仍 0 | 不需要私有路径 |

公开基础列指 `public`。补充公开 91/92 窗口字段、NSEvent 带窗口号点击、touch subtype
均未改变坐标点击/滚动结论。私有窗口字段列指 `private-fields`，不合成焦点，仍公开 postToPid。
`private-focus-fields`、`private`、`private-tagged`、`private-sky-tagged` 也未补上 Electron 点击；
这些失败行中页面未收到 mousedown/mouseup/click。AXPress 的返回码不是成功判据。

单键码的私有分组失败时仍收到 `a` 的 keyDown/keyUp，却未插入文本：`private-fields`
两种目标各 1/3 成功；`private-tagged` Electron 2/3、AppKit 1/3；`private` 首轮两者均失败。
这些 backend 在键盘分支也设置了公开窗口字段，部分还合成焦点或换投递函数；没有足够对照
把不稳定精确归因到某个字段、焦点或动作顺序。推荐键盘继续用 `public` 路径，私有增强只研究鼠标。

推测：Electron 整串和逐字符的差异表明事件构造/文本接收路径是关键变量，不能简单归为
“Chromium 没有后台键盘焦点”。点击未到 DOM 的具体原因仍未知；合成焦点候选未改善结果，
但不排除缺少其他焦点状态、事件字段或处理阶段。这里未恢复官方完整焦点算法。

## 权限与失效证据审计

系统日志时间（测试机本地时区）：15:57:43 记录专用包的辅助功能变更，
15:58:52.900 起 PID 22875 查询权限，访问主体与授权主体均为专用探针包；
Accessibility/PostEvent/ListenEvent 查询结果为允许。因此已读到的那次 true 晚于系统授权记录，
没有证据表明它借用了终端或正式 Litch 的权限。系统日志不能确定用户消息的发送时刻。

另一方面，PID 22875 退出后旧 `permissions.json` 确实残留；旧读取缺少新鲜度校验。
这是真实缺陷，已修成活进程 + 最近三秒 + 实例 UUID + 自身责任进程检查。
更早轮次不作为矩阵证据。窗口选择也修正为 PID/层/可见性/精确几何唯一匹配；
早期按 PID 取第一个窗口可能选中隐藏菜单栏，相关结果一律不参与结论。

本轮未读写 TCC 数据库、未替换已授权的正式应用。责任进程诊断调用私有只读接口，
与公开输入组的输入/焦点路径分开。用户另给探针打开过屏幕录制，但本探针不采集屏幕，
也未调用屏幕录制请求。测试结束可撤掉探针的辅助功能和屏幕录制两项授权。
